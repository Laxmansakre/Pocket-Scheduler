How to use Pocket Scheduler

Layout is currently tuned for: —

1. Building the activity list

Add rows with + Activity. Each row is a Task, a Milestone (zero duration, shown as a diamond), an Event (a fixed date you pick directly — useful for inspections, deliveries, client visits — that other activities can still depend on), or a Level of Effort (see below).

2. Level of Effort activities

Some activities — supervision, project management, site security — don't have a duration of their own; they simply last as long as the work they support. Set an activity's Type to Level of Effort and its Duration becomes automatic: give it an SS predecessor link to whatever it should start alongside, and an FF predecessor link to whatever it should finish alongside, and its Start, Finish, and Duration are all calculated from those links. For example, Supervision might have Predecessors A2SS (starts with Mobilization) and A9FF,A10FF (finishes with whichever of the last two activities finishes later).

3. WBS & grouping

The WBS column uses dot codes to build the hierarchy: 1, 1.1, 1.1.1. Any row that has children automatically becomes a summary row — its duration, Start/Finish, predecessors and successors are disabled and instead auto-calculated from its children's dates. Rows sort automatically by WBS code.

Note on linking two peer activities to each other

If activity B depends on A, and A also depends on B — in any combination of relationship types — that's a genuine circular reference, and Pocket Scheduler will flag it, the same way P6 would. This usually comes up when trying to say "these two run in parallel, and something should wait for whichever finishes later." The fix isn't to link A and B to each other — it's to link a third, downstream activity to both of them as FS predecessors. CPM automatically uses the later of the two finishes when computing that third activity's start, with no special relationship type needed.

4. Duration & units

Set a number and a unit per row: hours, days, weeks, or months. Internally a week counts as 5 working days and a month as roughly 20 working days, so the schedule math stays consistent regardless of which unit is most natural for a given activity.

5. Predecessors & Successors

Type a comma-separated list into either column — they're two views of the same link, so editing one updates the other automatically. Format: A2 (defaults to Finish-to-Start, no lag), or explicitly A3SS+2, A4FF-1, A5SF.

  • FS Finish-to-Start — the default. B can't start until A finishes.
  • SS Start-to-Start — B can't start until A starts.
  • FF Finish-to-Finish — B can't finish until A finishes.
  • SF Start-to-Finish — B can't finish until A starts. Rare, but supported.
  • +lag / -lead — a number of working days added or subtracted, e.g. FS+3 waits 3 extra days, SS-2 allows a 2-day head start.

A row with no predecessor and/or no successor gets a small ! badge next to its ID — that's a heads-up, not necessarily an error (every project legitimately has one open start and one open finish), but worth a glance if it shows up somewhere unexpected.

6. The calendar

Click 📅 Calendar to set which days of the week count as working days, and to add specific holiday/closure dates. Everything downstream — Start/Finish dates, the Gantt bars, float — respects this calendar.

7. Reading the Gantt chart

Bars in the orange hazard-stripe pattern are on the critical path — any delay to them delays the whole project. Grey bars with pointed ends are summary rollups. Diamonds are milestones. Use the + / − zoom buttons to change how many days are visible at once. Drag a column's right edge in the table to resize it.

8. Printing & exporting

The Print / PDF button offers three layouts — Table only, Gantt only, or Table + Gantt side by side — plus a choice of timescale (Days through Yearly). Large schedules automatically continue across as many pages as needed, both across dates and down through activities, the same way Primavera P6 paginates a big schedule. Use Export CSV for a spreadsheet copy, and Save .json / Open… to back up or hand off a project file.

9. Your data

Everything runs in your browser — there's no server and nothing is uploaded. Your project autosaves locally as you work, but clearing your browser's site data will erase it, so it's worth using Save .json for anything you don't want to risk losing.
